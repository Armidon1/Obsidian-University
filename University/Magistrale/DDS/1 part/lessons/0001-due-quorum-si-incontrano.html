DDS / verso il masking quorum / lezione 1 / 5 minuti

Non puoi aspettare tutti.
Ma due gruppi si incontrano.

Alla fine saprai calcolare quante risposte puoi aspettare e quanti server hanno in comune una write e una read. Sono i due conti che stanno dietro al masking quorum.

Per ora i server possono solo fermarsi. I server bugiardi arrivano nella lezione 2.
SchedaSlide 18

1. Quante risposte puoi aspettare?

Un registro è una variabile copiata su N server. Al massimo f possono guastarsi. Il client manda la richiesta a tutti e aspetta le risposte.

Il sistema è asincrono: un server lento e uno morto sembrano uguali. Quindi si possono aspettare al massimo le risposte di chi è sicuramente vivo.

risposte aspettabili = N − f

Il gruppo di risposte che aspetti si chiama quorum, e la sua dimensione si indica con Q.

2. Prova a far sbagliare la read.

Una write è finita dopo 3 risposte: S1, S2 e S3 hanno il valore nuovo. Ora scegli tu quali server rispondono alla read.

Q = 3. Cerca 3 server senza il valore nuovo.

Q = 2. Stessa prova: la write ha raggiunto solo S1 e S2.

3. Perché con 3 non ci riesci.

Write e read occupano 3 + 3 = 6 posti, ma i server sono solo 5. Almeno un server deve stare in entrambi i gruppi. In generale:

server in comune ≥ Q + Q − N = 2Q − N

CasoContoRisultato
N = 5, Q = 36 − 5almeno 1 in comune: la read trova il valore
N = 5, Q = 24 − 5anche 0 in comune: la read può mancarlo

Fonte: Cachin, Guerraoui, Rodrigues, Introduction to Reliable and Secure Distributed Programming, § 2.7.3 “Quorums”.
