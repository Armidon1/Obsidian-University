# SHA-256 (Secure Hash Algorithm 256-bit)

**Tag:** #crittografia #hash #SHA2 #sicurezza #standard #NIST

## 1. Definizione
**SHA-256** è una funzione hash crittografica appartenente alla famiglia **[[SHA-2]]** (Secure Hash Algorithm 2).
Progettata dalla NSA e pubblicata dal NIST nel 2001, trasforma un input di lunghezza arbitraria in un output di lunghezza fissa di **256 bit** (32 byte), chiamato *digest* o *hash*.

## 2. Caratteristiche Tecniche
- **Dimensione Output:** 256 bit (32 byte).
- **Dimensione Blocco Input:** 512 bit (64 byte).
- **Dimensione Word:** 32 bit.
- **Rounds:** 64 iterazioni per ogni blocco.
- **Struttura:** Costruzione di [[Merkle–Damgård]] con una funzione di compressione Davies-Meyer.
- **OID (Object Identifier):** `2.16.840.1.101.3.4.2.1` (Utilizzato nei certificati e in [[PKCS#1]] per indicare l'algoritmo).

## 3. Proprietà di Sicurezza
SHA-256 è progettato per soddisfare tre proprietà fondamentali:
1. **Resistenza alla Pre-immagine ([[One-Way Function (OWF)]]):** Dato un hash $H$, è computazionalmente impossibile trovare un messaggio $M$ tale che $\text{Hash}(M) = H$.
2. **Resistenza alla Seconda Pre-immagine:** Dato un input $M_1$, è impossibile trovare un input diverso $M_2$ tale che $\text{Hash}(M_1) = \text{Hash}(M_2)$.
3. **Resistenza alle Collisioni:** È computazionalmente impossibile trovare due messaggi qualsiasi $M_1$ e $M_2$ tali che $\text{Hash}(M_1) = \text{Hash}(M_2)$.
* *Forza:* Richiede circa $2^{128}$ operazioni per trovare una collisione (Paradosso del Compleanno).

## 4. Utilizzo nei Protocolli (Contesto RSA)
SHA-256 è onnipresente negli standard moderni discussi nelle note precedenti:

- **[[RSA-OAEP]] (Cifratura):**
Viene utilizzato all'interno della **[[Mask Generation Function (MGF)|MGF1]]** e come funzione hash principale per fare l'hashing dei parametri. Aggiunge "robustezza crittografica" e lega il messaggio al seed casuale.
- **[[RSA-PSS]] (Firma Digitale):**
Nel paradigma "Hash-then-Sign", il messaggio viene prima processato con SHA-256 per ottenere un digest corto e fisso, che viene poi firmato. Questo è essenziale per l'efficienza (RSA è lento su dati grandi) e per la sicurezza.
- **[[PRG|CS-PRNG]]:**
Viene spesso usato per "mescolare" (hash together) diverse fonti di entropia (movimenti mouse, timing tastiera, ecc.) per generare un seed sicuro.

## 5. Funzionamento (Semplificato)
1. **Padding:** Al messaggio viene aggiunto un bit '1', seguito da zeri, e infine la lunghezza del messaggio originale (in 64 bit). Il totale deve essere un multiplo di 512.
2. **Inizializzazione:** Si parte con 8 costanti a 32 bit (valori hash iniziali presi dalle radici quadrate dei primi 8 numeri primi).
3. **Processamento Blocchi:** Il messaggio viene processato in blocchi da 512 bit. Ogni blocco passa attraverso 64 round di operazioni bitwise (XOR, AND, Rotazioni, Shift).
4. **Concatenazione:** Lo stato finale dei registri viene concatenato per formare l'hash di 256 bit.

## 6. Confronto
| Algoritmo | Output (bit) | Sicurezza Collisioni | Stato Attuale |
| :--- | :--- | :--- | :--- |
| **MD5** | 128 | **Rotto** (molto facile) | Deprecato. |
| **SHA-1** | 160 | **Rotto** ($< 2^{63}$) | Deprecato (legacy only). |
| **SHA-256** | 256 | Sicuro ($2^{128}$) | **Standard Industriale.** |
| **SHA-512** | 512 | Sicuro ($2^{256}$) | Standard (per 64-bit CPU). |
| **SHA-3** | Variabile | Sicuro | Alternativa moderna (Keccak). |
