Conflict-serializability.

Conflitto = transazioni diverse + stesso elemento + almeno una write. Read-read mai; stessa transazione mai.

  1. Riscrivi S in una colonna per elemento, in ordine.
  2. In ogni colonna, per ogni azione, guarda quelle successive di altre transazioni: se almeno una delle due è una write, arco Tprima → Tdopo.
  3. Cerca un ciclo (anche di due nodi: Ti → Tj e Tj → Ti).
  4. Ciclo → non conflict-serializable. Aciclico → conflict-serializable; il seriale equivalente è un ordine topologico (togli via via un nodo senza archi entranti).

2PL: lock esclusivi, poi condivisi.

Regole: well-formed (lock prima di ogni azione), legale (niente lock incompatibili insieme), due fasi (dopo il primo unlock, nessun lock, upgrade compresi). Con soli lock esclusivi anche read-read è incompatibile; con S/X no.

  1. Ciclo nel precedence graph → non 2PL in entrambe le versioni (2PL ⇒ CSR).
  2. Per ogni Ti: il primo unlock forzato è il primo uso incompatibile, da parte di un’altra transazione, di un elemento che Ti ha già usato.
  3. Ogni elemento che Ti usa dopo quel punto va bloccato prima. Se un altro lo usa in modo incompatibile in mezzo, o se è lo stesso elemento ceduto → non 2PL.
  4. Nessun ostacolo → 2PL: scrivi lo schedule con i lock.

Strict e rigorous.

Recoverablecj, se Tj legge da Ti

Strictogni read o write di un altro su un elemento scritto da Ti (w-r, w-w)

serial ⊂ rigorous ⊂ strict ⊂ ACR ⊂ recoverable. Rigorous ⇒ CSR nell’ordine dei commit; strict ⇏ CSR (r1(x) w2(x) c2 w1(x) c1). Strict 2PL ⇒ strict; SS2PL ⇒ rigorous. Commit mancanti: subito dopo l’ultima azione della transazione.

Inserting the missing commits right after each transaction's last action:
w1(x) c1 r2(y) w3(y) c3 w2(x) c2. S is strict: w2(x) follows c1.
S is not rigorous: r2(y), w3(y) conflict but c2 is not between them.
