# Test-Driven Development

> [!summary] In breve
> Tecnica di progettazione in cui si scrive prima un test che fallisce per il codice che si vorrebbe avere, poi il codice minimo per farlo passare, poi si fa refactoring.

- Non riguarda davvero il testing: è **design** (obbliga a decidere l'interfaccia prima).
- Produce codice più pulito, con separazione delle responsabilità.
- Ciclo [[Red-Green-Refactor]], strumento [[RSpec]].
- Rispetto al debugging tradizionale: stesse tecniche, più produttivo; più tempo all'inizio, meno nel complesso.
